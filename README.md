# 🎵 คิวเพลง (Qsix)

ระบบต่อคิวเพลงแบบเปิดเครื่องเอง (self-hosted) — วางลิงก์เพลงจากหลายแพลตฟอร์มเข้าคิวเดียว
แล้วเล่นต่อเนื่องจนจบคิว เปิดจากมือถือ/แท็บเล็ตในเครือข่ายเดียวกันได้ และต่อเสียงออก **ทีวี / ลำโพง**
ผ่าน DLNA หรือเลือกอุปกรณ์เสียงของเครื่องได้

## ✨ ความสามารถ

- **หลายแพลตฟอร์มในคิวเดียว** — วางลิงก์จาก YouTube, Spotify, SoundCloud, Bandcamp และอีกหลายร้อยเว็บ
  (ใช้ `yt-dlp`) แสดงป้ายกำกับ platform ให้รู้ว่าเพลงมาจากไหน
  - ลิงก์ Spotify จะถูกแปลงไปเล่นเวอร์ชันบน YouTube ให้อัตโนมัติ (Spotify บล็อกการดาวน์โหลด/สตรีมตรง)
- **คิวต่อเนื่อง** — เพิ่ม/ลบ/เลื่อน/เล่นเลย/ข้าม/ย้อน/ล้างคิว เพลงเล่นจบแล้วเลื่อนเพลงถัดไปเองจนหมดคิว
  (เพลงที่โหลดไม่ได้จะถูกข้ามอัตโนมัติ)
- **ค้นหา** — ไม่มีลิงก์? ค้นหาชื่อเพลง/ศิลปิน แล้วเพิ่มจากผลลัพธ์ได้เลย
- **ต่อออกทีวี / ลำโพง (DLNA)** — กด "ค้นหา" เพื่อหาอุปกรณ์ MediaRenderer บนเครือข่าย (สมาร์ททีวี,
  soundbar, ลำโพง Wi-Fi) แล้วกด Cast — เซิร์ฟเวอร์จะคุมคิวให้เล่นต่อเนื่องจนจบ
- **เลือกแหล่งเสียง (เครื่องที่ออกเสียง)** — เห็นทุกเครื่องที่เปิดแอปอยู่ เลือกได้ว่าเพลงจะออกเสียงจากเครื่องไหน
  (เครื่องอื่นกลายเป็นรีโมตสั่งเล่น/ข้าม/seek ได้) เครื่องแรกที่เปิดจะได้เป็นแหล่งเสียงอัตโนมัติ
- **เลือกอุปกรณ์เสียงของเครื่อง** — ใช้ Chrome/Edge เลือกได้ว่าออกลำโพงตัวไหน (`setSinkId`)
- **ซิงก์ทุกหน้าจอ** — เปิดจากมือถือเพิ่มเพลงได้ หน้าจออื่นอัปเดตสดผ่าน SSE

## 📦 สิ่งที่ต้องมี

- [Node.js](https://nodejs.org) 16 ขึ้นไป
- Python 3.8+ (ใช้สำหรับ `yt-dlp` — ติดตั้งให้อัตโนมัติในโฟลเดอร์ `venv/` ของโปรเจกต์)

## 🚀 วิธีเริ่มใช้งาน

```bash
npm install        # ติดตั้ง dependencies ฝั่งเซิร์ฟเวอร์
npm run setup      # สร้าง venv + ติดตั้ง yt-dlp (ครั้งแรกครั้งเดียว)
npm run build:web  # build หน้าเว็บ React + MUI ไปที่ web/dist
npm start          # เปิดเซิร์ฟเวอร์ที่ http://localhost:5173
```

> ระหว่างพัฒนาโค้ดหน้าเว็บ: `cd web && npm run dev` (พอร์ต 5174 พร้อม proxy ไป backend)
> แล้ว build ใหม่ด้วย `cd web && npm run build` ก่อนใช้งานจริง

จากนั้น:

1. เปิด `http://localhost:5173` บนเครื่อง หรือ `http://<IPเครื่อง>:5173` จากมือถือ/แท็บเล็ตใน Wi-Fi เดียวกัน
   (โปรแกรมจะแสดง URL ให้ตอนเปิด)
2. วางลิงก์เพลง (หรือสลับไปโหมดค้นหา) แล้วกด **เพิ่มเข้ารอ** — เพลงแรกเล่นทันที
3. กด **📺 ต่อออกทีวี / ลำโพง** → **🔄 ค้นหา** → เลือกอุปกรณ์ → **Cast**
4. ใช้ตัวเลื่อนเสียงข้างล่างปรับความดัง (ปรับได้ทั้งในเครื่องและตอน cast)

> เปลี่ยนพอร์ตได้: `PORT=8080 npm start`

## 🔌 API หลัก

| เมธอด | เส้นทาง | ความหมาย |
|---|---|---|
| `GET` | `/api/queue` | ดูคิวเพลง |
| `POST` | `/api/queue` | เพิ่มลิงก์ (`{ url, playNow? }`) |
| `POST` | `/api/search` | ค้นหา (`{ q }`) ได้ผลลัพธ์ 5 เพลง |
| `DELETE` | `/api/queue/:id` | ลบเพลง |
| `POST` | `/api/queue/:id/move` | เลื่อน (`{ dir: -1/1 }`) |
| `POST` | `/api/queue/:id/play-now` | เอาเพลงขึ้นมาเล่นเลย |
| `POST` | `/api/control` | `{ action: play/pause/next/prev/stop }` |
| `GET` | `/api/stream/:id` | สตรีมเสียง (รองรับ Range/seek) |
| `GET` | `/api/devices` | ค้นหาอุปกรณ์ DLNA |
| `POST` | `/api/cast` | `{ deviceId, action: start/stop/volume }` |
| `GET` | `/api/events` | อีเวนต์สด (SSE) — ส่ง `clientId`/`name` เพื่อลงทะเบียนเครื่อง |
| `GET` | `/api/clients` | รายชื่อเครื่องที่เชื่อมต่อ + แหล่งเสียงปัจจุบัน |
| `POST` | `/api/clients/master` | เลือกแหล่งเสียง (`{ clientId }`) |
| `POST` | `/api/clients/name` | ตั้งชื่อเครื่อง (`{ clientId, name }`) |

## 🛠️ โครงสร้าง

```
server.js          เซิร์ฟเวอร์ Express + API + proxy สตรีม + cast
src/resolver.js    แปลงลิงก์จากทุกแพลตฟอร์มเป็นข้อมูลเพลง + ลิงก์สตรีม (yt-dlp)
src/queue.js       คิวเพลง (หน่วยความจำ) + การเลื่อน/ข้าม/เล่นซ้ำ
src/dlna.js        ค้นหาและควบคุมอุปกรณ์ DLNA/UPnP (SSDP + SOAP/AVTransport)
src/cast.js        จัดการเซสชัน cast — เล่นต่อเนื่องจนจบคิว
web/               หน้าเว็บ React + MUI (Material UI) + Material Icons
scripts/setup.js   ติดตั้ง yt-dlp ใน venv ของโปรเจกต์
```

หน้าเว็บเป็น React + MUI — แก้โค้ดที่ `web/src/` แล้ว build (`cd web && npm run build`)
เซิร์ฟเวอร์จะเสิร์ฟผล build จาก `web/dist/` ให้อัตโนมัติ

## ⚠️ หมายเหตุ

- คิวอยู่ในหน่วยความจำ — รีสตาร์ทเซิร์ฟเวอร์แล้วคิวจะหาย (ยังไม่มีฐานข้อมูล)
- ไม่มีระบบ login — เหมาะกับใช้ในบ้าน/ปาร์ตี้บนเครือข่ายส่วนตัวเท่านั้น
- การเล่นอัตโนมัติอาจถูกเบราว์เซอร์บล็อก (Autoplay Policy) — ระบบจะเล่นแบบเงียบให้อัตโนมัติ
  แล้วแสดงปุ่ม "เปิดเสียง" (แตะที่หน้าเว็บตรงไหนก็เปิดเสียงได้) เบราว์เซอร์ที่อนุญาตจะเล่นมีเสียงตามปกติ
- YouTube อาจตอบ 403 เป็นระยะ (บล็อกบอต) — ระบบจะลองดึงลิงก์ใหม่ให้อัตโนมัติ ถ้ายังไม่ได้ให้ลองเพลงอื่น
